# VectorUmovPoynting

Тривимірна візуалізація плоских електромагнітних хвиль і вектора Умова–Пойнтінга
**S = E × B / μ₀** (PyQt6 + PyQtGraph). Застосунок показує, як поля E і B однієї хвилі
переносять енергію вздовж напрямку поширення k, і що відбувається, коли дві хвилі
від різних джерел ідуть назустріч одна одній і утворюють стоячу хвилю.

## Можливості

### Вкладки

| Вкладка | Що показує |
|---|---|
| **Хвиля 1 — (0,0,0)** | Хвиля від джерела в початку координат: E, B і S. |
| **Хвиля 2 — Довільне джерело** | Хвиля від джерела в довільній точці (координати в λ). |
| **Суперпозиція (1+2)** | Дві зустрічні хвилі: джерела вмикаються при t = 0, фронти рухаються одне до одного, а в зоні перекриття малюється сумарне поле E₁+E₂, B₁+B₂ і його S. |

### Параметри хвилі

- поляризація: лінійна, кругова (права/ліва), еліптична;
- амплітуда E, зсув фази, довжина відображуваного відрізка (у λ);
- напрямок поширення: одна з осей ±X, ±Y, ±Z або довільний вектор;
- початкові напрямки E і B (±X/±Y) для потоку вздовж ±Z — програма стежить, щоб
  E ⊥ B і E × B збігався з напрямком поширення;
- модуляція AM, FM або AFM (частота та індекс).

### Суперпозиція

- **Відстань між джерелами** — від 0,5 до 20 λ, типово 8 λ (фронти зустрічаються через 4 T).
  Джерело 1 — у початку координат, джерело 2 — у напрямку, заданому на вкладці «Хвиля 2».
- Кнопки моментів часу: **Старт** (фронти щойно вийшли з джерел), **Зустріч** (фронти
  зустрічаються посередині), **Пізніше** (повне перекриття, стояча хвиля) і крок ±T/20.
- У точці зустрічі показано напрямки k, E, B обох хвиль, а після зустрічі — миттєві
  E₁, B₁, E₂, B₂ та сумарні EΣ, BΣ у масштабі поля.
- Перемикач «Окремі хвилі в зоні перекриття» прибирає окремі хвилі там, де намальовано суму.

### Відображення і дані

- подання: лінії (криві полів і стрілки S) або поверхні (стрічки полів і трубка S);
- компоненти: усі (E, B, S), лише E або лише B;
- проєкція, масштаб (пікселів на λ; синхронізується з коліщатком миші), чорний або білий фон;
- таблиця значень: E (В/м), B (нТл), S (Вт/м²) — показано лише ненульові компоненти;
- збереження і завантаження параметрів (JSON), збереження малюнка разом із таблицею.

### Кольори

Колір позначає фізичну величину, відтінок — хвилю:

| Величина | Хвиля 1 | Хвиля 2 | Сума (Σ) |
|---|---|---|---|
| E | синій | блакитний | фіолетовий |
| B | червоний | лососевий | рожевий |
| S | бурштиновий | блідо-жовтий | золотий |
| k | зелений | світло-зелений | — |

Осі координат сірі й підписані X, Y, Z; усі осі спрямовані в додатному напрямку, тож
система координат на екрані завжди права.

## Фізична модель

- Несуча частота фіксована: 1 Гц, отже T = 1 с, λ = c, і фронт проходить 1 λ за період.
  Координати у 3D-вигляді виміряно в λ.
- Поля задано через запізнювальний час τ = t − s/c, де s — відстань від джерела вздовж k;
  B = (k̂ × E) / c, S = E × B / μ₀.
- У суперпозиції кожна хвиля існує лише там, куди встиг дійти її фронт
  (s ≤ c·t), тож видно, як хвилі виходять зі своїх джерел і зустрічаються.

## Запуск

Потрібен Python 3.12 або новіший.

**З uv** (версії з `uv.lock`):

```bash
uv sync
uv run python main.py
```

**З pip** (версії з `requirements.txt`):

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt        # Windows: .venv\Scripts\pip ...
.venv/bin/python main.py                         # Windows: .venv\Scripts\python main.py
```

## Тести

```bash
python -m unittest discover -s tests -p "test_*.py"
```

Тести GUI будують справжнє вікно на платформі Qt `offscreen`, тож дисплей не потрібен.
На кожен push і pull request тести запускає GitHub Actions (`.github/workflows/tests.yml`).

## Файли параметрів

Параметри зберігаються як JSON зі `schema_version: 3`; налаштування записано
стабільними ключами (`"combined"`, `"axis"`, `"black"` …), а не текстами інтерфейсу.
Файли старіших версій (1 і 2) перетворюються автоматично під час завантаження.

## Структура проєкту

| Модуль | Призначення |
|---|---|
| `main.py` | Точка входу. |
| `main_window.py` | Головне вікно: стан інтерфейсу, обробники, збереження/завантаження, перемальовування. |
| `controls.py` | Панель керування та підписи для збережених значень. |
| `scene.py` | 3D-сцена: осі, стрілки напрямків, поля, стрілки в точці зустрічі. |
| `simulation.py`, `physics.py` | Розрахунок полів E, B, H, S для однієї хвилі та зустрічних хвиль. |
| `superposition.py` | Моменти часу, розміщення джерела 2, текст стану (без Qt). |
| `geometry.py` | Системи відліку хвиль, стрілки, грані поверхонь. |
| `models.py` | Параметри та перелічення (enum) налаштувань. |
| `persistence.py` | Формат файлів параметрів, перевірка та міграція. |
| `camera.py`, `palette.py`, `legend.py`, `data_table.py`, `renderer.py` | Камера, кольори, легенда, таблиця, набори графічних елементів. |

## Залежності

Версії зафіксовано: точні — у `requirements.txt` і `uv.lock`, допустимі діапазони — у
`pyproject.toml`. Щоб оновити: `uv lock --upgrade`, перенести нові версії в
`requirements.txt`, запустити тести.

## Docker

Оскільки це GUI-застосунок, запуск у Docker потребує X11 forwarding.

### Підготовка

**Linux** — дозвольте підключення до X-сервера:

```bash
xhost +local:docker
```

**Windows** (VcXsrv або Xming):
1. Встановіть [VcXsrv](https://sourceforge.net/projects/vcxsrv/).
2. Запустіть `XLaunch` з налаштуваннями:
   - "Multiple windows"
   - "Display number" = 0
   - **Важливо:** увімкніть "Disable access control".

### Збірка та запуск

1. Зберіть образ:
   ```bash
   docker build -t poynting-viz .
   ```

2. Запустіть контейнер:

   **Linux:**
   ```bash
   docker run -it --rm \
     -e DISPLAY=$DISPLAY \
     -v /tmp/.X11-unix:/tmp/.X11-unix \
     poynting-viz
   ```

   **Windows (PowerShell):**
   ```powershell
   # Замініть <YOUR_IP> на IP-адресу вашого хоста (не 127.0.0.1)
   docker run -it --rm `
     -e DISPLAY=<YOUR_IP>:0 `
     poynting-viz
   ```

   Або через Compose: `docker compose up --build`.

### Примітка щодо OpenGL

Якщо в контейнері виникають помилки ініціалізації OpenGL, додайте прапорець
`--device /dev/dri:/dev/dri` (лише Linux із підтримкою GPU) або увімкніть програмний
рендеринг: `LIBGL_ALWAYS_SOFTWARE=1`.
